# Genealogy methodology: the standards layer

The professional discipline behind the project's evidence rules. Sources: BCG (bcgcertification.org/ethics-standards), Evidence Explained QuickLessons 11+17, Family Locket / Research Like a Pro, Legacy Tree.

## Genealogical Proof Standard (GPS): a conclusion is sound only when ALL five hold
1. **Reasonably exhaustive research**: checked the sources a competent researcher would; not just the first hit.
2. **Complete and accurate source citations**: every claim traceable.
3. **Thorough analysis and correlation**: records weighed against each other, not accepted singly.
4. **Resolution of conflicting evidence**: conflicts explained, not ignored (our CONFLICT-note rule).
5. **Soundly reasoned, written conclusion**: the proof-ledger entry / research-note paragraph.
GPS maps directly onto the project's proof-ledger bands: PROVEN ≈ GPS met for that edge.

## Three analytical layers: never collapse into one "primary source" label
- **SOURCE (container):** Original (register image, certificate) > Derivative (index row, abstract, database extract) > Authored narrative (member tree, family story, memoir).
- **INFORMATION (content):** Primary (informant had firsthand knowledge) vs Secondary (hearsay: e.g. parents' birthplaces on a death cert from next-of-kin) vs Undetermined. One document mixes qualities: a death cert is primary for the death, secondary for the birth.
- **EVIDENCE (vs the question):** Direct / Indirect (needs combining) / **Negative** (meaningful absence: e.g. not in an exhaustively-searched index ⇒ died elsewhere/later).
Practical triad: index entry = derivative, verify against the image; register image = original, prefer it; member tree/family story = authored narrative, hypothesis only.

## Identity control (anti-conflation)
- **Never merge on name + approximate year alone** (the lesson of two cousins sharing a name and a decade). Require ≥2 independent anchors: parents, exact date+place, spouse, consistent residence chain.
- **Timeline consistency:** two-places-at-once, impossible ages, childbearing-span, marriage-age checks kill bad matches fast (a 3yo on an electoral roll).
- **FAN club (Friends/Associates/Neighbors) / cluster research:** when the target left thin records, research the cluster: witnesses, neighbours, siblings' records name the target. Also THE tool for separating same-named people (whose neighbours/parish/occupation chain is this?).
- **On a field mismatch, enumerate the innocent explanations before rejecting/accepting:** remarriage ("formerly X" = prior MARRIED name of a widow, not maiden), occupation drift, index mangles, age rounding, nickname/middle-name swaps (May↔Mavis).

## Negative evidence & search logs
- **Negative search result** ("looked in X, not found") ≠ **negative evidence** (absence that MEANS something given expected presence). Both get documented.
- Log format: collection + dbid + name-forms tried + date window + result. Purpose: nobody re-runs a dry search in 5 years. (The "confirmed absent from collection X under maiden and married name" pattern.)

## Citations (pragmatic layered form for a personal GEDCOM)
Layered cite: database layer + original layer. Our NOTE-based GEDCOM pattern satisfies this:
`Source: Ancestry "India, Select Births and Baptisms, 1786-1947" (dbid 9899; FHL film 527471; original: FamilySearch India Births & Baptisms 2013). Folded YYYY-MM-DD.`
Minimum fields: collection title, dbid, film/reg/cert number where shown, original-data provenance, access date.

## Research planning (Research-Like-a-Pro loop ≈ our working loop)
question → analyze what's held → locality/collection study → plan → execute with a log → written conclusion. Stop ("reasonably exhaustive") when ≥2 independent, agreeing information items and the obvious sources are consumed or documented dry.
