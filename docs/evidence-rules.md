# The evidence rules

Project law. The agent never bends these; a reviewer should be able to audit any fold
against them.

1. **Primary records fold; trees corroborate.** Member trees, FamilySearch profiles,
   Geneanet and smart matches are leads only, logged in the ledger, never folded alone.
   The one sanctioned carrier for tree-sourced people is the imported second tier: tagged,
   quality grade 1, ring 4, stripped from every upload. It is not a fold.
2. **Provenance is one source.** A platform's "Select" collection that was extracted from
   FamilySearch is the same source as FamilySearch. Twenty trees copying one profile are
   one source. Agreement between copies is not corroboration.
3. **Never fold on name alone.** Require at least two independent identity anchors
   (parents, exact date and place, spouse) before attaching a record. Age-impossible and
   place-implausible hints are false matches: a three-year-old is not on an electoral roll.
4. **Conflation is the enemy.** Same-name relatives merge in shared trees. On any date or
   parent mismatch, weigh remarriage, widowhood and two-people explanations before
   accepting or rejecting. Split conflated people; leave unproven parentage unlinked with
   a sourced note saying why.
5. **Document negatives, and qualify them.** "Confirmed absent from collection X under
   maiden and married name, positive control returned rows" goes in the register so nothing
   is re-run. A nil without a control, or in a corpus whose coverage of that place and period
   is unknown, is recorded as coverage-unknown and never closes a gap. A zero returned while
   rate-limited is void, not a nil.
6. **Flag conflicts, do not resolve them silently.** Two credible values get a note with
   both and what would decide between them.
7. **Snapshot before every edit; verify after.** Counts, zero dangling references,
   connectivity unchanged unless the edit intended otherwise.
8. **Cite everything folded.** Collection name, database id, film or registration number
   where shown, original-data provenance, fold date.

Two corollaries that were learned the hard way:

- A fact can carry a registration citation and still hold an estimated date. Verify the
  value, not just the presence of a citation.
- A record-level source pointer is not a fact-level one. A citation audit that only reads
  fact-level pointers under-counts, and one that only reads record-level ones cannot say
  which fact is supported.
